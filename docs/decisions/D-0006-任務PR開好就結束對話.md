# D-0006 任務的 PR 開好就結束對話;送出一律走 `ship`

| | |
|---|---|
| 狀態 | 提案(沿用範本,待專案成員確認) |
| 日期 | 2026-11-27(沿用範本) |
| 決定者 | 沿用工作流範本;本專案成員確認後改寫 |
| 範圍 | `CLAUDE.md` §3、§7;`.claude/skills/ship` 第 7 步;交接檔範本 |
| 相關 | 補充 D-0002 第 6 點 |

## 決定

1. **任務的 PR 開好(交接檔已在 PR 內覆寫)就結束這段對話**:回報結尾附交接檔裡的新對話開場白,下一個任務開新對話。使用者在同一段對話追加別的任務時,先建議開新對話;使用者要在這裡做才繼續。
2. **送出一律用 `ship`**,不手動 commit / 開 PR。
3. 「對話很長時問一次是否交接」限定在任務**中途**;任務結束時不問,直接依第 1 點附開場白。
4. 交接檔範本加「新對話開場白」一節,讓第 1 點有固定來源。

## 理由

- D-0002 第 6 點只說「下一個任務開新對話」,沒有說由誰、在哪一步提出;實際運作時 Claude 開完 PR 就直接接下一件事,觸發點要掛在 `ship` 的最後一步才會被執行。
- 從範本建立的專案實際發生過:Claude 手動 commit 與開 PR、沒走 `ship`,漏掉交接檔覆寫,主分支上的交接檔留著已被否決的做法。
- 任務結束時再問「要不要交接」是多一輪來回;答案幾乎都是要,直接附開場白即可。
