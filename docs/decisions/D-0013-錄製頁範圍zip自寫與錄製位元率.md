| | |
|---|---|

| 相關 | 補充 D-0009(編輯與保存)、D-0011(錄製預設);`docs/SCHEMA.md` 版本 1 |

## 決定

1. **錄製頁第一版的範圍:** 錄步驟、步驟列表的重錄、刪除、排序、插入、修剪頭尾,以及匯出、匯入 zip 套件。IndexedDB 自動暫存(D-0009 第 2 點)下一個 PR 做;在那之前,離開頁面時有未匯出的步驟就提示。
2. **zip 自己寫,不加套件:** 寫出時不壓縮(影片、JPEG 本來就壓過);讀取時支援不壓縮與 deflate,deflate 用瀏覽器原生的 `DecompressionStream('deflate-raw')`。不支援 ZIP64(單一套件 4 GB 以上)。
3. **錄製位元率依像素數自動算:** `MediaRecorder` 的中間檔每百萬像素(放大後)約 4 Mbps,下限 4 Mbps、上限 20 Mbps;不在頁面上給選項。存進套件的 H.264 用 mediabunny 的「高」畫質重新編碼。
4. **頁面:** 錄製頁放在首頁(`index.html`);M1 實測頁搬到 `m1.html` 保留,之後補測 M1 用。
5. **Claude 擬定:**
   - 錄好一段就轉成 H.264 MP4 與海報圖,步驟在記憶體裡只存這一份(匯出時不必再轉)。
   - 匯入時 `manifest.json` 可以在 zip 根目錄,或在唯一的上層資料夾裡(解壓後用作業系統重新壓縮時常見)。
   - 匯入時 `id` 不合規則或重複就產生新的並提示;缺海報圖就從影片重新產生;其他必填欄位不合規則的步驟不載入並提示(`docs/SCHEMA.md` §3)。
   - `size` 匯出時一律依目前第一步的框選計算;第一步被刪掉或換掉,尺寸跟著變。
   - **匯入不信任 zip 的上限:** 最多 2000 個項目、單一檔案解壓後 1 GB、`manifest.json` 1 MB、500 步、框選座標與寬高 16384 像素。只解壓 `manifest.json` 與它引用的檔案;邊解邊數大小與 CRC,超過中央目錄宣告的大小或 CRC 不符就中止。重複檔名、`.`、空的路徑段都拒絕。框選取整數、寬高往下取偶數。
   - 沿用的框選(匯入或重錄)超出目前的畫面時不錄,提示重新框選。

## 理由

- **範圍:** 暫存要處理版本、清除與復原提示,獨立一個 PR 比較好審;沒有暫存時,匯出的 zip 本來就是專案檔,不會沒有地方保存。
- **匯入上限:** zip 是使用者自己選的檔案,但可能來自別人;沒有上限時,宣告很小、實際解壓到 GB 級的 zip 會讓分頁當掉(`rules-security-reviewer` 2026-11-27 指出)。上限取一般教學用不到的數量級。
- **zip 自己寫:** 只需要「不壓縮寫出」與「讀回來」,不壓縮的 zip 格式很單純(檔頭、CRC32、中央目錄);deflate 讀取交給瀏覽器原生 API,所以不加依賴,也不必走 `CONVENTIONS.md` §1 的套件審查。要能讀 deflate,是因為使用者可能把套件解壓、改過再用 Windows 或 macOS 重新壓縮。
- **位元率依像素數:** 框選一小塊時 4 Mbps 已經夠,2× 整個視窗(約 800 萬像素)6 Mbps 偏低(`docs/RESEARCH.md` §5);中間檔之後會重新編碼,給高一點只多佔記憶體,不影響套件大小。固定值不是浪費就是不夠。不給選項,實際使用不夠再調。
- **實測頁保留:** `docs/PENDING.md` §1 還有 M1 補測項目要用它。

## 已知限制與取捨

- 不支援 ZIP64:單一套件不能超過 4 GB。
- 匯出時每個檔案會同時以 Blob 與讀出的位元組存在記憶體,大套件匯出時記憶體約兩倍。
- 匯入時不檢查影片是不是真的 H.264 MP4;播放不了時在修剪區提示。
- 下一個 PR 做暫存之前,重新整理或關掉頁面就會失去未匯出的步驟(有離開提示)。(2026-11-27 由 D-0014 補上暫存)
