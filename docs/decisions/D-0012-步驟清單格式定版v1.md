# D-0012 步驟清單格式定版為版本 1

| | |
|---|---|
| 狀態 | 有效 |
| 日期 | 2026-11-27 |
| 決定者 | 使用者回「照建議」(Visy,2026-11-27) |
| 範圍 | 步驟清單與播放套件格式(`docs/SCHEMA.md`),錄製頁、轉檔、播放元件共用 |
| 相關 | 補充 D-0009、D-0011;否決 R-018 |

## 決定

1. **`docs/SCHEMA.md` 定版為格式版本 1。** `trim` 用 `currentTime` 的精準度不擋定版,改到播放元件的任務實機驗證(Chrome、Edge、Safari);不夠準先在播放元件裡處理,仍不行才寫新決策改成匯出時重新編碼。
2. **每一步加必填的 `scale`(`1` 或 `2`)**,記錄錄製時的放大倍率。
3. **`video`、`poster` 只能是套件裡的相對路徑**:不能是網址、不能以 `/` 開頭、不能含 `..` 或反斜線。錄製頁匯入與播放元件讀取時都檢查。
4. **放上網頁的是解壓後的資料夾**,播放元件讀 `manifest.json` 的網址;zip 用來傳遞與拖回錄製頁編輯。播放元件不讀 zip。
5. **`player.advanceAfterLoops` 是套件的預設值**,播放元件的屬性可以覆寫。
6. **`poster` 取修剪後的第一格**,修剪起點改了就重新產生。
7. **步驟 `id` 是 6 碼小寫英數**,同一份套件裡不重複。
8. **版本處理:** `format` 不對或沒有 `version` 時拒絕讀取;版本較新時播放元件照常播、錄製頁提示可能遺失欄位;版本較舊時讀取時轉成目前版本。

## 理由

- **第 1 點:** 不管播放元件怎麼控制起訖,`trim` 欄位的寫法都一樣,精準度只影響實作,不影響格式;錄製頁要先有定版的格式才能開始做。
- **第 2 點:** 2× 超過編碼上限時會自動降 1×(D-0011 第 4 點),同一份套件可能混用兩種倍率。用影片尺寸除以框選尺寸推算也行,但要先解碼影片,且編碼器可能把尺寸調成偶數,算出來不是整數。
- **第 3 點:** 套件可能是別人給的,拖進錄製頁,或放到別的網站給播放元件讀。限制在套件內,避免 manifest 讓瀏覽器去載入外部網址,或讀到套件以外的檔案。
- **第 4 點:** 播放元件要直接讀 zip 就得帶一個解壓套件,放進每個使用它的網頁;解壓後的資料夾用一般的網址就能讀,影片也能邊下載邊播。
- **第 5 點:** 同一份教學放在不同頁面,可能一處要自動前進、一處不要,不必為此另存一份套件。
- **第 6 點:** 修剪就是為了去掉開頭切回畫面的那一兩秒(D-0009 理由),用修剪前的第一格當海報會露出這段畫面。
- **第 7 點:** 檔名與 DOM 會用到 `id`,只用小寫英數不必處理跳脫;6 碼在一份套件的步驟數量內幾乎不會重複,產生時再檢查即可。
- **第 8 點:** 格式寫明版本,日後改欄位時舊套件還能讀(`CLAUDE.md` §8「處理舊版清單」)。
