# D-0009 步驟編輯、保存方式、播放元件的樣子、單檔的步驟編號

| | |
|---|---|
| 狀態 | 有效 |
| 日期 | 2026-11-27 |
| 決定者 | 第 1 ~ 3 點使用者回「照建議」;第 4 點使用者決定(Visy,2026-11-27);第 5 點 Claude 擬定而未逐項確認,有異議可改 |
| 範圍 | 錄製頁、播放元件、轉檔 |
| 相關 | D-0008、`docs/SCHEMA.md` |

## 決定

1. **步驟編輯:** 錄製頁的步驟列表可以重錄、刪除、拖拉排序、在任意位置插入新步驟,並修剪每步的開頭與結尾(時間軸拖兩個把手定起訖)。每步的播放速度、結尾定格這次不做。
2. **保存:** 匯出的播放套件(zip:步驟清單 + 每步影片)本身就是專案檔,拖回錄製頁就能繼續編輯;還沒匯出的進度用 IndexedDB 自動暫存。正本只有套件一份。
3. **播放元件:** 一個畫面循環播放目前的步驟,下方一排步驟編號按鈕與上一步、下一步;可設定播完 N 次自動前進到下一步。
4. **單一 MP4 與動圖的步驟編號:** 匯出時讓使用者選要不要在畫面角落燒步驟編號徽章(只有數字,不算說明文字)。
5. **Claude 擬定:**
   - 框選範圍:第一步框選,之後各步沿用,可以單獨改。同一份套件各步的輸出尺寸一致,以第一步為準;框選比例不同的步驟等比縮放後置中,四周補底色。
   - 播放元件做成 Web Component(例:`<step-reel src="…/manifest.json">`),不依賴框架,任何網頁都能放。
   - 修剪不重新編碼:套件裡存原始錄影,修剪起訖寫在步驟清單,由播放元件與轉檔依起訖播放、裁切。實際可不可行在 M1 實測時確認。

## 理由

- 修剪是最常需要的:每步開頭常錄到按下錄影後切回畫面的那一兩秒。
- 套件就是專案檔,畫面改版時只要拿出套件重錄那一步,不必另外管理一份專案檔;放進使用它的專案 repo 就有版本紀錄。只存在瀏覽器的話,換電腦或清快取就沒了。
- 單畫面加編號列佔版面最小,在手機上也好用;循環播放讓使用者有時間看清楚一步。
- 單檔沒有播放元件,看的人分不出現在是第幾步;但放進簡報時可能已經另外標了,所以讓匯出的人自己選。
- 修剪寫在清單、不重新編碼:編輯快、不損畫質,重剪也不必重錄。

## 否決的方案

| # | 方案 | 否決原因 | 重啟條件 |
|---|---|---|---|
| R-008 | 專案只存在瀏覽器(IndexedDB) | 換電腦或清快取就沒了 | 無 |
| R-009 | 專案檔(含原始錄影)與播放套件分開存 | 兩份檔案要管,容易不一致 | 套件裡的影片壓縮到明顯影響重新匯出的畫質時 |
| R-010 | 單檔在步驟之間插全畫面編號卡 | 拉長影片、動圖變大 | 角落徽章在實際使用時看不清楚 |
