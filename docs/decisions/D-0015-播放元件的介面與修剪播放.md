## 決定

1. **用法:** `<step-reel src="<資料夾>/manifest.json" advance-after-loops="2">`。
   - `src` 相對於目前頁面;影片、海報路徑相對於 manifest(轉址後以最後的網址為準)。
   - `advance-after-loops` 覆寫套件的 `player.advanceAfterLoops`;沒有這個屬性就用套件的設定,`0` 不自動前進。
   - 方法 `go(index)`、`next()`、`prev()`,屬性 `currentIndex`、`stepCount`;`setManifest(manifest, resolve)` 不經網址直接給 manifest(試播頁的 zip 預覽用,錄製頁日後預覽也可以用)。
   - 事件:`ready`(步驟數)、`stepchange`(`{ index }`)、`loop`(每播完一次,含量測用的時間)、`error`(`{ message }`)。
   - 樣式:Shadow DOM,用 `::part()`(`wrap`、`stage`、`video`、`play-icon`、`error`、`nav`、`button`,編號鈕另有 `step`,兩端另有 `prev`、`next`)與 `--step-reel-accent`、`--step-reel-line` 調整。
2. **畫面:** 舞台比例用 manifest 的 `size`(沒有就用影片本身的比例),影片等比縮進舞台,四周是 `background`;最寬不超過 `size.width`,2× 錄的影片顯示回框選的尺寸。下方是「‹ 1 2 3 … ›」;編號列只有數字,按鈕的無障礙名稱是「第 N 步」「上一步」「下一步」(D-0008 第 3 點:畫面上不放說明文字)。
3. **播放:** 自動循環播放目前的步驟(靜音、`playsinline`);點畫面暫停或繼續,暫停時顯示播放圖示。系統設定「減少動態」時一開始不自動播放,點畫面才播。最後一步播完不回到第一步,繼續循環。
4. **修剪的播放方式(`docs/SCHEMA.md` §6):** 起點用 `currentTime` seek;終點三層檢查:`requestVideoFrameCallback` 每格檢查「下一格會不會超過終點」,超過就先跳回起點;`requestAnimationFrame` 檢查播放時間(畫面不動、沒有新格時);分頁在背景時由 `timeupdate` 檢查。修剪終點等於影片結尾時,播到 `ended` 再跳回。
5. **路徑:** 除了 `docs/SCHEMA.md` §3 的檢查,解析成網址後還要在 manifest 所在的資料夾裡;不符合的步驟略過並在 console 警告。manifest 上限 1 MB(同 D-0013 第 5 點)。讀不到或格式不對時,元件裡顯示錯誤訊息並送出 `error` 事件。
6. **散布:** 另外打包成單一 ES module `dist/step-reel.js`(不含其他依賴,gzip 後約 5 KB),網頁用 `<script type="module">` 載入。`player.html` 是試播頁:可輸入 manifest 網址或選 zip 預覽,並量測修剪精準度,可複製結果。格式驗證的共用部分放在 `src/format.ts`,播放元件不引用錄製頁的 zip、轉檔模組。

## 理由

- **屬性覆寫套件設定:** D-0012 第 5 點;同一份套件放在不同頁面可以有不同的自動前進。
- **最後一步不繞回:** 教學是有順序的,播到最後跳回第一步會讓人以為又開始了一次;要重看可以點編號。
- **減少動態:** 循環播放的動畫對設定了「減少動態」的人不友善;一次點擊就能播,成本很低。
- **終點用「下一格會超過」判斷:** `requestVideoFrameCallback` 在一格出現之後才通知;等看到超過終點的那一格再跳回,那一格已經顯示出來了。提前一格跳回,畫面停在終點前的最後一格,等 seek 完成。螢幕錄影是變動格率(畫面不動時不送新格,CONVENTIONS「螢幕分享的格率低於設定值」),所以還需要依播放時間的檢查。
- **解析後再檢查資料夾:** 網址解析會把 `%2e%2e` 當成 `..`,只檢查字串擋不住。
- **單獨打包:** D-0009 第 5 點要「任何網頁都能放」;一個檔、沒有依賴,複製到別的網站就能用,也不會把錄製頁的轉檔函式庫帶進去。

## 驗證

| 項目 | 方式 | 結果 | 日期 / 誰 |
|---|---|---|---|
| 修剪起訖、循環 | 內建瀏覽器(Chromium)試播頁,M1 的 H.264 樣本做 3 步(兩步有修剪終點、一步修到結尾),每步循環 2 ~ 4 次 | 沒有播過頭;跳回後第一格是包含起點的那一格;跳回時畫面停約 17 毫秒(一個畫面更新),看不出閃爍。修到結尾的一步第一次跳回停 86 毫秒 | 2026-11-27 Claude |
| 自動前進、編號列 | 同上,`advance-after-loops="2"` | 播完 2 次到下一步,最後一步停在原地循環;上一步、下一步在兩端停用 | 2026-11-27 Claude |
| 路徑檢查 | 同上,manifest 放 `../x.mp4`、`steps/%2e%2e/%2e%2e/x.mp4` | 兩步都略過並警告 | 2026-11-27 Claude |
| zip 預覽、海報、底色 | 試播頁選 zip(錄製頁的 `exportZip` 產生) | 2 步、海報與底色正確,從修剪起點播 | 2026-11-27 Claude |

**尚未驗證:** Edge、Safari(Mac、iPhone)的修剪精準度與循環閃爍;放上 GitHub Pages(HTTP 範圍請求)後的 seek;真實多步錄影的套件;手機的觸控操作。

## 已知限制與取捨

- 換步驟時重新載入影片,下一步的影片沒有預先載入;網路慢時換步驟會先看到海報。實際使用有問題再改成預先載入。
- Vite 開發伺服器找不到檔案時回傳首頁的 HTML,錯誤訊息會是「不是有效的 JSON」而不是 HTTP 404;放上 GitHub Pages 時是 404。
