## 5. 踩過的坑

### 另開的 worktree 佔住 `main`

- **現象:** 收尾時主 repo `git switch main` 失敗:`'main' is already used by worktree at '…'`;已合併的本機分支 `git branch -d` 也刪不掉(要 `-D`)。
- **根因:** 同一條分支只能在一個資料夾簽出。為了平行開發另開的 worktree,合併後下一段對話直接把它當工作目錄,收尾時在裡面切到 `main`,`main` 就被那個 worktree 佔住;主 repo 停在舊的功能分支上,`-d` 拿那條分支比對,所以說沒合併。
- **之後:** `after-merge` 先用 `git worktree list` 分出主 repo 與另開的 worktree:另開的 worktree 不切 `main`,檢查乾淨後移除,切 `main`、更新、刪分支都在主 repo 做;別的 worktree 佔著 `main` 時先問使用者。移除條件見 D-0004 第 7 點。
- **來源:** 工作流範本

### 驗證指令接管線,失敗被當成通過

- **現象:** 本機回報 lint 通過,PR 的 CI 卻在 lint 失敗。
- **根因:** 驗證時用 `npm run lint 2>&1 | tail -1 && ...`;管線的結束代碼是最後一個指令(`tail`)的,lint 的失敗被吃掉。
- **之後:** 驗證指令不接管線;一定要接時先 `set -o pipefail`。
- **來源:** 工作流範本

### 影片錄螢幕顏色變淡、字不銳利

- **現象:** 錄下來的 UI(尤其深色底上的彩色細字)顏色比實際淡,邊緣糊;加大位元率也沒改善。
- **根因:** 影片編碼(H.264、VP9、AV1)和有損的動態 WebP 都用 4:2:0 色度取樣,顏色的解析度只有四分之一。合成畫面量測:6 Mbps 下彩色像素只保留約 7 成飽和度。
- **之後:** 錄製時把畫面放大 2×(像素直接複製,不內插),播放時縮回原尺寸;飽和度回到約 87%,亮度誤差從 3.7 降到 0.2 ~ 0.5。檔案大約變成 2 倍以上。
- **來源:** M1 實測(`docs/RESEARCH.md` §5)

### 螢幕分享的格率低於設定值

- **現象:** 要求 60 fps,錄出來平均只有 24 fps。
- **根因:** `getDisplayMedia` 的格率是上限;畫面沒變動時瀏覽器不送新格。
- **之後:** 看格率時看實際平均值,不要用設定值推算大小或流暢度。
- **來源:** M1 實測(`docs/RESEARCH.md` §5)

### 畫面不動的一段轉檔後只剩零秒

- **現象:** 錄一段畫面幾乎不動的步驟,轉成 MP4 後長度是 0(只有一格)。
- **根因:** 螢幕分享在畫面不動時不送新格;`MediaRecorder` 的 WebM 也不記最後一格的長度,轉檔時最後一格的長度是 0。
- **之後:** 轉檔時把最後一格延長到實際錄影的時間(`src/convert.ts` 的 `encodeVideo` 的 `minDuration`);錄製頁傳入 `Recording.wallSeconds`。
- **來源:** 錄製頁實作時用合成畫面發現(D-0013)

### GIF 的每格時間

- **現象:** GIF 總長度比原影片長(45 秒的錄影多將近 1 秒)。
- **根因:** GIF 每格時間只能記到 10 毫秒,15 fps 的 66.7 毫秒每格各自進位成 70 毫秒,誤差累積。另外,短於 20 毫秒的格,瀏覽器會當成 100 毫秒播放,所以 GIF 做不到 60 fps。
- **之後:** 每格時間由累計時間換算(`src/convert.ts` 的 `spanMs`);GIF 格率不超過 50 fps。
- **來源:** M1 實測(`docs/RESEARCH.md` §5)

### 內建瀏覽器窗格隱藏時,計時與播放不準

- **現象:** 在內建瀏覽器量播放元件的修剪精準度,量到播過頭好幾秒;重量一次又正常。
- **根因:** 窗格隱藏時頁面被當成背景分頁,`requestAnimationFrame`、`requestVideoFrameCallback` 每秒只跑一兩次(`document.hidden` 仍是 `false`)。
- **之後:** 量時間、格率、播放前先用 `tabs_context` 確認窗格是顯示的,隱藏時請使用者打開;播放元件本身也加了 `timeupdate` 的備援(D-0015 第 4 點),背景分頁不會卡住。
- **來源:** 播放元件實作時發現(D-0015)

### 內建瀏覽器不能驗證 Service Worker

- **現象:** 在 Claude 桌面版的內建瀏覽器開正式建置,Service Worker 註冊失敗。
- **根因:** 內建瀏覽器的限制。
- **之後:** 離線行為用 Playwright、一般瀏覽器或真實手機驗證。
- **來源:** 工作流範本(只在做 PWA 時適用)
